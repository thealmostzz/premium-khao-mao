# Quick Order via LINE Design

วันที่: 2026-07-05
สถานะ: Draft for review
ขอบเขต: เพิ่มฟอร์มสั้นในส่วน Final CTA ของหน้าแรก เพื่อช่วยให้ลูกค้าส่งข้อมูลคำสั่งซื้อเบื้องต้นเข้า LINE ได้ครบขึ้นโดยไม่ต้องมี backend

## 1. เป้าหมาย

- ลดแรงเสียดทานก่อนเริ่มแชทกับร้าน
- ทำให้ข้อความที่ส่งเข้า LINE มีข้อมูลพร้อมใช้งานมากขึ้น
- รักษาแนวทางเดิมของเว็บที่ปิดการขายผ่าน LINE เป็นหลัก
- เพิ่ม conversion โดยไม่ทำให้ Hero หนักหรือรบกวนการอ่านบนมือถือ

## 2. แนวทางที่เลือก

เลือกใช้ฟอร์มแบบ `สั้นแต่ฉลาด` วางใน section `Final CTA` เท่านั้น

เหตุผล:
- ผู้ใช้ที่เลื่อนมาถึงท้ายหน้ามีแนวโน้มพร้อมสั่งหรือพร้อมสอบถามมากกว่า
- ไม่เพิ่มภาระสายตาใน Hero ซึ่งยังควรเน้นความเร็วในการตัดสินใจ
- ใช้ JavaScript ฝั่งหน้าเว็บประกอบข้อความและเปิด LINE link ได้ทันที โดยไม่ต้องพึ่งระบบหลังบ้าน

## 4. โครงสร้างฟอร์ม

ตำแหน่ง: ใต้ข้อความและเหนือปุ่ม CTA หลักใน `Final CTA`

ฟิลด์:
- `สินค้า` แบบ select
  - ใช้รายการสินค้าที่มีในเว็บ
  - มีตัวเลือก `อื่นๆ`
- `รายละเอียดสินค้าเพิ่มเติม` แบบ text input
  - แสดงเมื่อเลือก `อื่นๆ`
- `จำนวน` แบบ select หรือ number input ที่จำกัดค่าต่ำสุดเป็น 1
- `ช่วงงบประมาณ` แบบ select
  - เช่น `ต่ำกว่า 500 บาท`, `500-1,000 บาท`, `1,000-2,000 บาท`, `มากกว่า 2,000 บาท`
- `งบที่ต้องการระบุ` แบบ number input
  - ไม่บังคับกรอก
- `ความเร่งด่วน / ช่วงเวลาที่ต้องการรับ` แบบ select
  - `ด่วนที่สุด`
  - `ภายใน 2-3 วัน`
  - `ภายใน 1 สัปดาห์`
  - `ระบุวันที่เอง`
- `วันที่ต้องการรับ` แบบ date input
  - แสดงเมื่อเลือก `ระบุวันที่เอง`
- `ปุ่มส่งข้อมูลไปทาง LINE`

## 5. พฤติกรรมการทำงาน

เมื่อผู้ใช้กดปุ่ม:
- ตรวจสอบว่ากรอกฟิลด์จำเป็นครบ
- ถ้าเลือก `อื่นๆ` ต้องกรอก `รายละเอียดสินค้าเพิ่มเติม`
- ถ้าเลือก `ระบุวันที่เอง` ต้องเลือกวันที่
- หากข้อมูลไม่ครบ ให้แสดงข้อความเตือนใกล้ฟิลด์หรือที่ส่วนบนของฟอร์ม
- หากข้อมูลครบ ให้ประกอบข้อความและเปิด LINE ด้วย URL scheme ปัจจุบันของร้าน

ตัวอย่างข้อความ:

```text
สวัสดีค่ะ สนใจสั่งซื้อสินค้า
- สินค้า: ข้าวเม่าคลุก
- จำนวน: 3 กล่อง
- ช่วงงบ: 500-1,000 บาท
- งบประมาณเพิ่มเติม: 900 บาท
- ต้องการรับ: ภายใน 2-3 วัน

รบกวนช่วยแนะนำรายการและรอบส่งที่เหมาะสมให้ด้วยค่ะ
```

กรณีพิเศษ:
- ถ้าเลือก `อื่นๆ` ให้แทรกบรรทัด `รายละเอียดเพิ่มเติม`
- ถ้าเลือก `ระบุวันที่เอง` ให้แสดงวันที่ในรูปแบบอ่านง่าย
- ถ้าไม่ได้กรอก `งบที่ต้องการระบุ` ให้ละบรรทัดนี้ออกจากข้อความ

## 6. การออกแบบ UX/UI

- ใช้เลย์เอาต์ที่ยังคงกลิ่นอายพรีเมียมและเข้ากับ `Final CTA` เดิม
- บน desktop จัดเป็น 2 คอลัมน์หรือกริดที่อ่านง่าย
- บน mobile เรียง 1 คอลัมน์เต็มความกว้าง
- ขนาด touch target ต้องเหมาะกับมือถือ
- ปุ่ม CTA ต้องเด่นกว่าฟิลด์ แต่ไม่ใหญ่จนบดเนื้อหาหลัก
- ฟอร์มควรดูเป็นส่วนต่อเนื่องของ CTA ไม่ใช่กล่องฟอร์มแยกแข็งๆ

## 7. ข้อมูลสินค้า

รายการสินค้าใน select ควรอิงจากรายการที่มีในหน้าเว็บ เพื่อให้ชื่อสอดคล้องกับคอนเทนต์จริง เช่น
- ข้าวเม่าคลุก
- ข้าวเม่าทอด
- ข้าวเม่าราง
- ชุดของฝากพรีเมี่ยม
- อื่นๆ

ถ้าชื่อที่แสดงในหน้าใช้ wording ที่ต่างออกไป ให้ยึดชื่อเดียวกับคอนเทนต์ปัจจุบันของหน้า

## 8. Validation และความปลอดภัย

- sanitize ข้อความจากช่อง `อื่นๆ` ก่อนนำไปประกอบข้อความ
- ใช้การใส่ค่าผ่าน `textContent`, `value`, และ `URLSearchParams` ไม่ใช้ `innerHTML` กับข้อมูลที่ผู้ใช้กรอก
- จำกัดความยาวข้อความช่อง `อื่นๆ` ให้อยู่ในขอบเขตที่เหมาะสม
- number input ต้องไม่ยอมรับค่าติดลบหรือศูนย์สำหรับจำนวน
- หาก date input น้อยกว่าวันปัจจุบัน ให้ถือว่าไม่ผ่าน validation

## 9. การรองรับภาษา

ต้องรองรับ `TH/EN` ตามระบบ i18n เดิม

รายการที่ต้องแปล:
- label ฟอร์ม
- placeholder
- ตัวเลือกสินค้า
- ตัวเลือกช่วงงบ
- ตัวเลือกช่วงเวลา
- ข้อความ error
- ข้อความ template ที่จะถูกส่งเข้า LINE

## 10. การวัดผล

ถ้าระบบ tracking ปัจจุบันรองรับ ให้ยิง event แยกจาก CTA เดิม เช่น
- เปิด LINE ผ่าน quick order form
- validation error ของ quick order form

หากการเพิ่ม event ทำให้เปลี่ยนโครงสร้างมากเกินจำเป็น ให้คง tracking แบบเรียบง่ายและไม่บล็อกการใช้งานหลัก

## 11. การทดสอบ

- ทดสอบ desktop และ mobile
- ทดสอบภาษาไทยและอังกฤษ
- ทดสอบกรณีเลือก `อื่นๆ`
- ทดสอบกรณีเลือก `ระบุวันที่เอง`
- ทดสอบกรณีกรอกไม่ครบ
- ทดสอบว่าข้อความใน LINE ถูก encode ถูกต้อง
- ทดสอบว่า CTA เดิมส่วนอื่นของหน้ายังทำงานปกติ

## 12. สิ่งที่ไม่ทำในรอบนี้

- ไม่เก็บ lead ลงฐานข้อมูลหรือ Google Sheet
- ไม่เพิ่มระบบแจ้งเตือนหลังบ้าน
- ไม่เพิ่มชื่อ เบอร์โทร หรือที่อยู่ในฟอร์ม
- ไม่ย้ายฟอร์มขึ้นไปไว้ใน Hero

## 13. ความเสี่ยงและแนวทางลดความเสี่ยง

- ถ้าฟอร์มยาวเกินไป conversion อาจลดลง
  - ลดด้วยการใช้เฉพาะฟิลด์ที่จำเป็นและซ่อนช่องตามเงื่อนไข
- ถ้าข้อความ LINE ยาวเกินไปบนมือถือบางรุ่น อาจดูใช้งานยาก
  - ลดด้วย template สั้น อ่านง่าย และตัดข้อมูลที่ไม่จำเป็นออก
- ถ้าชื่อสินค้าใน select ไม่ตรงกับคอนเทนต์หน้าเว็บ จะทำให้สับสน
  - ลดด้วยการอ้างอิงชื่อจาก content ปัจจุบันโดยตรง
